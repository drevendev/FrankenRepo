# План развития FrankenRepo и партнёрских интеграций

Следующий апдейт подробно описан в [спецификации v0.2](NEXT_UPDATE_SPEC_RU.md)
от 31 октября 2026. Доступы и кредиты уточнены в [аудите](ACCESS_CHECK_RU.md).
Ниже сохранён исходный roadmap от 28 октября; его ранние пометки об отсутствии
аккаунтов и приоритеты уточняются этими документами.

28 октября 2026, Asia/Nicosia. Цель — публичная демка с настоящей Gemma,
запоминающимися карточками и максимальным числом осмысленных партнёрских
интеграций. Деплой, регистрации и подключения отложены по просьбе владельца;
следующие пункты являются планом работ.

Все внешние ресурсы должны обходиться без карты, расходов, платного
автопродления и автоматического повышения тарифа. Бесплатный аккаунт сам по себе
не подтверждает бесплатность нужной функции. Каждую интеграцию считаем готовой
после работающего сценария и сохранённого доказательства.

## Первая очередь

1. **Публичная демка — Render и Gemma.** Развернуть лабораторию, проверить
   настоящий ритуал через публичный URL, сохранить карточку и доказательства.
2. **Надёжные лимиты.** Сохранять бюджет вызовов после рестартов, разделить
   посетителей за прокси, показывать оставшуюся локальную квоту.
3. **Постоянные карточки — MongoDB Atlas.** Добавить сохранение монстров,
   ссылки, добровольную публикацию в галерее и удаление владельцем.
4. **Оркестрация — Mastra.** Оформить инспекцию, генерацию, проверку и экспорт
   как наблюдаемый workflow.
5. **Трассировка — Sentry Agent Tracing.** Видеть этапы ритуала, задержки,
   ошибки и repair-попытки без записи секретов.
6. **Более осмысленные монстры.** Проверять вклад обоих доноров, требовать
   конкретный механизм полезной мутации и сохранять удачные и слабые результаты.
7. **Проверка публичного сайта — Browserbase.** Реальный облачный браузер
   проходит ритуал и проверяет экспорт.

Для первого публичного сценария нужны пункты 1–2; добавление галереи требует
пункта 3 вместе с согласием на публикацию и удалением. Остальные интеграции
не должны задерживать работающую демку.

## Следующая очередь

8. **ElevenLabs.** Озвучивать первые слова монстра по кнопке, если бесплатная
   лицензия подходит для публичной демки.
9. **SerpApi.** Добавить дополнительные источники для идей мутаций с явными
   ссылками и разделением внешнего контекста и фактов о донорах.
10. **Auth0 for AI Agents.** Управлять личными карточками и разрешениями на
    публикацию; гостевой ритуал сохранить доступным без входа.
11. **Backboard.** Добавить память вымышленной родословной при скрещивании.
12. **Temporal.** Восстанавливать прерванные ритуалы без повторного списания
    вызовов; согласовать границы ответственности с Mastra.
13. **Tiger Data.** Искать похожих монстров и сочетания доноров после
    накопления галереи.
14. **Ultramarine.** Использовать отдельного редактора для проверки
    наследования и конкретики идеи при наличии подходящих бесплатных кредитов.
15. **Entire.** Сохранить настоящие записи агентной разработки для статьи.
16. **GitHub Copilot.** Получить реальное участие в разработке или ревью
    с сохранённым результатом; не выдавать сессию Codex за использование Copilot.

## Направления для отдельной оценки

17. **TabPFN.** Анализировать результаты оценки карточек после накопления
    реальных данных, если это даст полезный вывод.
18. **Tinker.** Рассмотреть обучение на отобранных примерах при доступных
    бесплатных кредитах и подходящих условиях.
19. **Arduino.** Сделать физический рычаг лаборатории, если устройство уже есть.
20. **DigitalOcean и .tech.** Рассмотреть дополнительный хостинг или домен
    только при подтверждённых условиях без карты, расходов и платного
    автопродления. Ради регистрации эти направления не запускать.

## Где понадобятся аккаунты

GitHub и Cloudflare уже используются. Для Gemma через существующий Cloudflare
отдельный аккаунт Google не нужен.

Сначала подготовить аккаунты следующих сервисов, если их ещё нет:

- [Render](https://dashboard.render.com/register) — хостинг демки; при создании
  сервиса выбирать именно Free compute, а не только бесплатный workspace.
- [MongoDB Atlas](https://www.mongodb.com/cloud/atlas/register) — база карточек
  и устойчивого состояния; целевой вариант — Free/M0, не Flex или платный кластер.
- [Sentry](https://sentry.io/signup/) — трассировка и ошибки; проверить нужные
  возможности бесплатного плана до активации.
- [Browserbase](https://www.browserbase.com/sign-up) — облачные браузерные
  проверки; использовать доступную Free-квоту.

Позже, по мере реализации соответствующей функции:

- [ElevenLabs](https://elevenlabs.io) — голос и проверка лицензии.
- [SerpApi](https://serpapi.com/users/sign_up) — ключ поиска.
- [Auth0](https://auth0.com/signup) — tenant и поддержка нужного сценария AI Agents.
- [Backboard](https://backboard.io) — память и API.
- [Tiger Data](https://www.tigerdata.com) — облачная база и поиск после проверки
  условий; ограниченный trial не считать постоянным бесплатным тарифом.
- [Paper Instruments](https://docs.paperinstruments.com/docs/ultramarine) —
  Ultramarine только при подходящих промокредитах. Обычный quickstart предлагает
  пополнение баланса; самостоятельно его не выполнять.
- [Tinker](https://tinker-docs.thinkingmachines.ai) — доступ к обучению и
  проверка промокредитов.
- [Prior Labs](https://priorlabs.ai) — если выберем облачный TabPFN;
  требования локального варианта проверим отдельно.

Для конкурса также пригодятся [DEV](https://dev.to/enter) для статьи и
[Hacktoberfest](https://hacktoberfest.com/my/promos) для доступных промо.
Если аккаунт уже есть, достаточно использовать его.

Mastra как локальному framework отдельная облачная регистрация не требуется.
Temporal можно использовать со своим сервером; аккаунт Temporal Cloud нужен
только при выборе облачного сервиса. Для Copilot используется существующий
аккаунт GitHub. Arduino потребует устройство, а не облачный аккаунт для рычага.
Доступ к Entire, локальным весам TabPFN и конкретным промопрограммам уточняется
после выбора способа интеграции.
